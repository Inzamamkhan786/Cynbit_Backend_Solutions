# Audit Findings Matrix: Cynbit Technologies Backend Assessment

This matrix catalogs all technical findings, security evaluations, architectural observations, and performance attributes identified during the technical audit of [https://www.cynbit.in](https://www.cynbit.in/).

---

| Finding ID | Category | Description | Public Evidence | Severity | Status | Potential Impact | Recommended Solution | Relevant Backend Implementation | Verification Method |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **FIND-01** | Validation & Usability | Vague, monolithic form error handling lacking field-level identification in Careers application | Client chunk `page-082725dddd6cb4ac.js` shows `b(s.error \|\| "Something went wrong...")` rendered in single top banner | **High** | Confirmed through public evidence | Severe user drop-off and frustration when filling out 15-field application forms with URL errors | Adopt RFC 9457 structured validation error format returning `{ errors: [{ field, message }] }` | `src/middleware/validateSchema.ts`, `src/modules/careers/careers.schema.ts` | Vitest unit & integration tests (`tests/integration/careers.test.ts`) asserting exact `portfolioUrl` field errors |
| **FIND-02** | Security Headers | Missing Content-Security-Policy (CSP) across all pages | HTTP response headers on `/`, `/careers`, `/contact` omit `Content-Security-Policy` | **High** | Confirmed through public evidence | Susceptibility to Cross-Site Scripting (XSS), malicious script injection, and unauthorized data exfiltration | Configure strict CSP directives via Helmet permitting only trusted scripts and styles | `src/middleware/securityHeaders.ts` (Helmet configuration) | Automated security header tests in `tests/integration/securityHeaders.test.ts` |
| **FIND-03** | Security Headers | Missing Clickjacking Protection (`X-Frame-Options` and `frame-ancestors`) | Missing `X-Frame-Options` and `frame-ancestors 'none'` in document response headers | **Medium** | Confirmed through public evidence | Malicious websites can embed Cynbit within an invisible iframe to perform clickjacking or credential harvesting | Enforce `X-Frame-Options: DENY` and `frame-ancestors 'none'` | `src/middleware/securityHeaders.ts` (`frameguard: { action: 'deny' }`) | Header assertions in `tests/integration/securityHeaders.test.ts` |
| **FIND-04** | Security Headers | Missing MIME-type sniffing protection (`X-Content-Type-Options: nosniff`) | Missing `X-Content-Type-Options` header across all responses | **Medium** | Confirmed through public evidence | Browsers may execute non-executable files (e.g. uploaded resumes) as scripts via MIME sniffing | Enforce `X-Content-Type-Options: nosniff` | `src/middleware/securityHeaders.ts` (`xContentTypeOptions: true`) | Integration test verifying presence of `nosniff` header |
| **FIND-05** | Information Disclosure | Server software exposure (`X-Powered-By: Next.js`) | Response headers on `/careers`, `/contact`, `/case-studies` include `X-Powered-By: Next.js` | **Low** | Confirmed through public evidence | Attackers can fingerprint the runtime framework and target known framework vulnerabilities | Strip `X-Powered-By` header in reverse proxy or application middleware | `src/middleware/securityHeaders.ts` (`hidePoweredBy: true`) | Supertest assertion in `tests/integration/securityHeaders.test.ts` |
| **FIND-06** | Access Control & CORS | Overly permissive wildcard CORS (`Access-Control-Allow-Origin: *`) on HTML pages | Response headers on `/`, `/services`, `/products` contain `Access-Control-Allow-Origin: *` | **Medium** | Confirmed through public evidence | Unauthorized third-party origins can interact with sensitive endpoints or read responses if cookies are mishandled | Implement strict origin allowlist matching authorized frontend domains | `src/middleware/securityHeaders.ts` (`corsMiddleware` allowlist) | Integration tests verifying CORS rejection on unauthorized origins |
| **FIND-07** | Rate Limiting | Lack of distributed rate limiting on public form write actions | Form actions lack `RateLimit-Limit`, `RateLimit-Remaining`, and `Retry-After` headers | **High** | User-reported and requiring verification | High-volume automated bots can flood contact inquiries, spam career applications, or exhaust email quotas | Implement Redis-backed sliding-window distributed rate limiter with atomic Lua script | `src/middleware/rateLimiter.ts` (`createRateLimiter` with Redis Lua) | Multi-instance rate limit tests in `tests/integration/distributedRateLimiter.test.ts` |
| **FIND-08** | Reliability & Ingestion | Synchronous email dispatch claim without outbox persistence | Contact form displays "INQUIRY RECEIVED. Team notified via email" synchronously | **Medium** | Confirmed through public evidence | Dropped or delayed emails during SMTP outages without durable retry capability | Implement Asynchronous Transactional Outbox pattern returning `HTTP 202 Accepted` | `src/services/email.service.ts`, `src/modules/contact/contact.service.ts` | Integration tests verifying `status: PENDING` and outbox record creation |
| **FIND-09** | Reliability & Idempotency | Absence of duplicate form submission protection (Idempotency) | Double-clicking contact or application submit dispatches duplicate server actions | **Medium** | Potential improvement | Multiple identical inquiries inserted into database; duplicate notification emails dispatched to team | Implement `Idempotency-Key` header validation and hash verification | `src/modules/contact/contact.repository.ts`, `src/modules/contact/contact.service.ts` | Integration test asserting cached response replay and conflicting hash 409 rejection |
| **FIND-10** | Validation & Data Integrity | Client-side email validation without strict backend sanitization | Newsletter modal passes raw form input directly to server action | **Medium** | Potential improvement | Trailing whitespace, case sensitivity issues, or excessively long strings entering subscriber database | Server-side Zod schema with whitespace trimming, lowercase conversion, and length caps | `src/modules/newsletter/newsletter.schema.ts` | Unit tests in `tests/unit/validation.test.ts` testing whitespace and normalization |
| **FIND-11** | Reliability & Observability | Absence of Request Correlation ID (`X-Request-Id`) | Responses from Cynbit production omit request correlation tracing headers | **Medium** | Confirmed through public evidence | Inability to correlate client-reported errors with server-side logs during incident triage | Inject unique `X-Request-Id` UUID on every request and propagate into structured logs | `src/middleware/requestId.ts`, `src/middleware/requestLogger.ts` | Integration tests verifying `X-Request-Id` propagation in response headers |
| **FIND-12** | Observability | Absence of public health / readiness probe endpoint | Probing `/health` or `/api/health` yields 404 Not Found on production | **Low** | Confirmed through public evidence | Load balancers and orchestration systems cannot evaluate database/redis readiness | Implement `/health` endpoint reporting database pool latency, Redis state, and memory | `src/routes/health.routes.ts` | Integration tests in `tests/integration/health.test.ts` asserting 200/207 telemetry |
| **FIND-13** | Database Constraints | Internal database schema constraints and connection pool configuration | Cannot inspect private PostgreSQL configuration from public web client | **N/A** | Not verifiable without authorized backend access | Potential connection pool exhaustion or lock contention during peak traffic spikes | Define parameterized queries, unique indexes, and bounded connection pool settings | `src/config/database.ts`, `src/database/migrate.ts` | Documented in `docs/architecture.md` |

## Evidential Legend
* **Confirmed through public evidence**: Verified directly through observable HTTP responses, network interactions, or client script decompilation.
* **User-reported and requiring verification**: Originally reported by the reviewer and subsequently validated or contextualized by this audit.
* **Potential improvement**: Best-practice architectural or resilience enhancements mapped directly to observed system gaps.
* **Not verifiable without authorized backend access**: Internal infrastructure attributes that cannot be ethically observed from public endpoints.
